# Rails 8.1 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the ETD Rails application from Rails 7.0.8.1 to the latest Rails release verified on June 23, 2026: Rails 8.1.3.

**Architecture:** Keep the existing application shape: Rails with Sprockets, jQuery, Action Text, Minitest, MySQL for normal operation, and SQLite/MySQL test coverage in CI. Upgrade one Rails minor at a time, keeping `config.load_defaults` behind the runtime version until each rung is green, then enabling new framework defaults deliberately.

**Tech Stack:** Ruby 3.4.9 target runtime, Bundler 2.5+, Rails 8.1.3, Sprockets asset pipeline, Puma, MySQL, SQLite test path, Minitest, Selenium system tests, Docker Compose, GitHub Actions.

- Ruby official downloads page lists Ruby `3.4.9` as a maintained stable release and Ruby `3.1.7` as not maintained anymore. Use Ruby `3.4.9` for this Rails upgrade; evaluate Ruby `4.0.5` after Rails 8.1 is green because this app has older dependencies.

## Known Upgrade Blockers

These are not theoretical; they are visible in the current `Gemfile.lock`.

- `validates_timeliness` from `mitsuru/validates_timeliness` branch `rails7` depends on `activemodel >= 6.0.0, < 7.1`. This blocks Rails 7.1 and newer.
- `audited 5.4.3` depends on `activerecord >= 5.0, < 7.2`. This blocks Rails 7.2 and newer.
- `exception_notification 4.5.0` depends on `actionmailer >= 5.2, < 8` and `activesupport >= 5.2, < 8`. This blocks Rails 8.
- `font-awesome-rails 4.7.0.8` depends on `railties >= 3.2, < 8.0`. This blocks Rails 8.
- `actiontext` is pinned to `~> 7.0`; Rails 8.1 needs the Rails-managed `actiontext 8.1.3`.
- `factory_girl_rails 4.8.0` is legacy. Replace with `factory_bot_rails` before or during the Rails 8 move to avoid test-framework friction.
- `exception_notification 5.0.1` supports Rails 8 but requires Rails `>= 7.1`, so update it after the Rails 7.1 rung, not on the initial Rails 7.0 baseline.
- `validates_timeliness 8.0.0` supports Rails 8 but requires Active Model `>= 8.0.0, < 9`, so keep the dependency unpinned and update it again during the Rails 8 rung.
- The app still uses `redirect_to :back` in `app/controllers/students_controller.rb`, which was removed long before modern Rails and should be replaced before the upgrade exposes it.
- The app relies on Sprockets, jQuery, CoffeeScript-era gems, and Bootstrap sprockets integration. Keep this stack during the Rails upgrade; do not combine the Rails upgrade with a JavaScript pipeline migration.

- `Gemfile.lock`: regenerated by Bundler at each rung.
- `config/application.rb`: keep `config.load_defaults 7.0` until each rung is stable; later advance to `7.1`, `7.2`, `8.0`, and `8.1` after framework defaults are reviewed.
- `config/environments/development.rb`, `config/environments/test.rb`, `config/environments/production.rb`: merge Rails-generated environment changes from `bin/rails app:update`.
- `config/initializers/new_framework_defaults_7_1.rb`, `config/initializers/new_framework_defaults_7_2.rb`, `config/initializers/new_framework_defaults_8_0.rb`, `config/initializers/new_framework_defaults_8_1.rb`: generated and worked through one default at a time.
- `config/initializers/cookies_serializer.rb`: review during Rails 7.1 cache/cookie serializer changes.
- `config/initializers/assets.rb`: keep Sprockets setup and merge only Rails-generated safe changes.
- `app/controllers/students_controller.rb`: replace `redirect_to :back`.
- `app/views/students/_student.html.erb` and `app/views/students/index.html.erb`: replace `fa_stacked_icon` helper usage before removing `font-awesome-rails`.
- `vendor/assets/stylesheets/font-awesome.css.erb` and `vendor/assets/fonts/*`: add vendored Font Awesome 4 assets from the existing gem so Sprockets can keep resolving the current icon CSS without the Rails-8-blocking gem.
- `test/test_helper.rb`: replace `FactoryGirl` with `FactoryBot` after switching gems.
- `test/factories.rb` and `test/factories/*.rb`: replace `FactoryGirl.define` with `FactoryBot.define`.
- `test/**/*.rb`: replace `FactoryGirl.create`, `FactoryGirl.build`, and `FactoryGirl` syntax with `FactoryBot` or included factory methods.
- `.github/workflows/rubyonrails.yml`: pin Ruby to the same `.ruby-version` path and keep both SQLite and MySQL test jobs.
- `README.md`: update development and test commands only after the runtime and test commands are verified.
